# Behavior risk matrix

- **Last updated:** 2026-10-26
- **Status:** Active
- **Scope:** Critical contracts and the limits of their evidence, not estimated coverage percentages

Use `pnpm test:inventory` for runner discovery. This matrix maps risks to behavioral tests;
passing status belongs to a specific local/CI run, not to this document.

| Boundary                  | Contract to retain                                                                                                                                                                  | Primary evidence                                                                                 | Remaining limit                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Authentication            | Signed identity determines profile/access; revoked sessions fail closed on sensitive routes                                                                                         | `apps/web/src/hooks.server.test.ts`                                                              | Built-app browser validation is paused; provider availability is outside these unit tests             |
| Billing                   | Real SDK verifies raw signatures; duplicate/retry handling, current provider state wins over delayed events; failed writes retry; checkout/portal ownership; frozen recovery access | `stripe-service.test.ts`, Stripe route tests, enabled hook guard tests                           | Mocked SDK/database calls do not prove live account configuration or concurrent exactly-once delivery |
| Automatic tier upgrade    | Threshold, stable idempotency key, local recovery after successful provider upgrade                                                                                                 | `stripe-service.test.ts`; enabled/disabled hook tests                                            | Independently gated; live proration/configuration remains separately approved                         |
| Campaign sending          | Shared daily allowance, exclusive claims, uncertainty accounting, suppression, authorization, save-before-queue                                                                     | Sender/route/UI tests; `email_campaign_daily_cap.check.sql`; `campaign_claim_races.py`           | No real mail delivery in these tests; migration must be deployed to activate the database fix         |
| Workspace and sharing     | User isolation, atomic invite acceptance, access walls, calendar projection, archived record exclusion                                                                              | Automatically discovered current-schema `.check.sql`; route tests                                | Pinned schema must be deliberately refreshed; mocks do not establish RLS                              |
| Chat lifecycle            | Cancellation/replay fencing, terminal recovery, stale UI response rejection, receipt cleanup, reader position                                                                       | Current-schema contracts; worker lifecycle tests; direct controller and rendered component tests | Built-app send/stop/reopen and mobile target geometry remain unverified                               |
| Built application         | Login, navigation/hydration, project/task editing across reload, chat send/stop/reopen, invite acceptance; mobile usability                                                         | Incomplete experimental harness in `apps/web/tests/browser`; no required CI lane                 | Paused at user request; this remains an open infrastructure gap                                       |
| Scheduling                | Exact UTC instants through spring gaps/fall overlaps; no past instant or second fall delivery                                                                                       | `apps/worker/tests/scheduler.comprehensive.test.ts`; shared Cycle scheduling tests               | Scheduling calculation does not prove actual external delivery timing                                 |
| Tool catalog              | Unique vocabulary, satisfiable schemas, registry dispatch alignment, required capabilities, bounded payload                                                                         | `catalog-fitness.test.ts`; `tool-surface-size-report.test.ts`; runtime registry tests            | Schemas alone cannot establish model tool-choice quality                                              |
| Agent Run costs/recovery  | Reservations, privilege fences, stranded proposal commit recovery                                                                                                                   | Dedicated worker integration config, disposable PostgreSQL                                       | Requires database binaries/connection; skipped local suites are not passing evidence                  |
| Validation infrastructure | Complete scorecards, model/account allowlists, deployment provenance, SQL classification and fixture composition                                                                    | Root Node/Python tests included in static gate                                                   | Tool tests complement actual runner execution; inventory alone is insufficient                        |

Prioritize a new regression when a real failure or changed boundary exposes a missing guarantee.
Do not add broad snapshots or a global coverage target to substitute for these contracts.
Use the fresh CI coverage artifact to investigate untested branches in high-risk modules.
